Yours to change

A tribunal that installs LexTribunalis receives its source code and may change it to suit itself. This page says how that is meant to work, and what part of it is not built yet.

You are not locked in

The source code is on your own server. Your IT staff can read it and change it. So can a coding agent, such as Claude Code or Codex: point one at the folder and ask for a field, a report or a screen to be added, removed or changed.

That is deliberate. A tribunal should not have to buy its tools from someone who alone can alter them, and it has never been easier to alter software than it is now.

The licence allows a tribunal to change its own copy as it likes. It does not allow passing the system on to others.

What an agent needs

A coding agent works quickly and is sometimes wrong, and it does not always say when. That matters little for the colour of a button. It matters a great deal if a change quietly alters when a time limit expires or which act must come before another.

An agent does its best work when there is something fixed that every change can be checked against, by a rule and not by another guess. For a tribunal, that fixed thing is the procedural law.

The graph of the procedure

LexTribunalis is being built to keep the procedural law as a graph. The word is from mathematics, and the idea is simple: a list of the acts of a process, and the rules that hold between them. This act cannot come before that one. This act opens that time limit, and that act closes it.

Each act and each rule cites its source in the Code of Canon Law, Dignitas connubii or Mitis Iudex.

Because it is a fixed set of rules, a computer can check a cause against it, or a change to the program against it, and give the same answer every time.

The graph is not written by an AI. It is Richard Verver's reading of the procedural law, set down rule by rule so that another canonist can check it and disagree with it. It is given a version number, and it is brought up to date when the law changes.

Its work is to constrain. Whatever a person or an agent changes in the program, the tests that come with the system will fail if the change would alter the procedure, so that nothing about the procedure changes without someone having decided it.

Where your practice differs

Not every tribunal follows every step as the law sets it out. Many have settled ways of working that serve their people well with the staff they have.

A tribunal will be able to edit its own copy of the graph to match its practice. The system then notes, at the points where it matters, that the tribunal's practice differs there from the Code, Dignitas connubii or Mitis Iudex. The note is there to inform and for no other reason.

A tribunal that does not want the notes can have them taken out, like anything else.

What is at your own risk

A copy that a tribunal has changed is the tribunal's own. Richard cannot answer for changes he has not seen, and an update from him may not fit a copy that has been altered.

Two parts deserve particular care: the rules on who may see what, and the record of changes. A careless alteration there is a breach of confidence and not a mere fault.

A tribunal that would rather not make a change itself can ask Richard to make it, for a fee agreed beforehand.

Where this stands today

  • The source code is delivered with every installation, with the tests that check the counting of time limits and the rules of access.
  • The steps of each process and the time limits attached to them are kept as plain lists, each with its canon beside it.
  • The rules between the steps, which make those lists a graph, and the checking of a cause and of the program against them, are being built now. They are not yet in the system.
